# Adapter capability matrix

Verified facts about each agent surface Tacet can drive. Written for issue #8. Rules: see the `verify-vendor-facts` skill and `.github/instructions/adapters.instructions.md`.

- **Checked** date for every row is **2026-11-09** unless a row says otherwise.
- **Status**: `verified` = read in a primary source on the checked date. `UNVERIFIED` = not confirmed from a primary source; do not build on it. `PARTIAL` = some of it confirmed, remainder noted.
- Sources are paraphrased. Each row has its own link.
- No vendor CLI was installed in the research environment, so "version" means the version the docs or schema state, or the repo ref read. Adapter authors must re-pin against the version they install (Codex: `codex app-server generate-json-schema`; OpenCode: `GET /doc`).
- Network note: `developers.openai.com`, `openai.com`, `opencode.ai`, `geminicli.com` and `agentclientprotocol.com` did not resolve from the research environment. Codex, OpenCode and Gemini facts therefore come from the vendors' GitHub repos (source, schema, docs files), which are primary. Anything that exists only on the blocked sites is marked UNVERIFIED.

## 1. Claude Code (Agent SDK and `claude -p`)

Two ways in: the Agent SDK (TS/Python, wraps the Claude Code binary) and the CLI `claude -p`. Both run the same agent loop.

| Capability | Fact | Status | Source |
|---|---|---|---|
| Surfaces / runtimes | TS package `@anthropic-ai/claude-agent-sdk` and a Python SDK. SDK `executable` option accepts `bun`, `deno` or `node` (auto-detected). `bun build --compile` needs `extractFromBunfs()` (v0.3.144+). Bundles a native Claude Code binary as an optional dependency; `pathToClaudeCodeExecutable` overrides it. | verified | https://code.claude.com/docs/en/agent-sdk/typescript , https://code.claude.com/docs/en/agent-sdk/overview |

Can stay pending indefinitely. `AskUserQuestion` also routes through it. `PreToolUse` hook can return `defer` so the process can exit and resume later. `PermissionRequest` hook exists. | Permission modes | `permissionMode` incl. `default`, `acceptEdits`, `auto`, `dontAsk`, `plan`, `bypassPermissions` (needs `allowDangerouslySkipPermissions`). | Interrupt | SDK `Query.interrupt()` (streaming input only). Observed on 2.1.319 (#64): receipt `{still_queued: []}`, and the interrupted turn's `result` has subtype `error_during_execution`. Resending a still-queued message that was not cancelled delivers it twice. CLI: SIGINT ends the turn; SIGTERM exits 143 and records no result for the in-flight turn. | verified | https://code.claude.com/docs/en/agent-sdk/typescript , https://code.claude.com/docs/en/headless |
| Resume / fork | `resume: <sessionId>`, `forkSession: true` (with resume, new session ID, original unchanged), `continue: true` (most recent in cwd). | Token / context usage | Per-step usage on assistant messages (dedupe by message id; per-step `output_tokens` is a placeholder). `result` has cumulative `usage` (main loop only, excludes subagents), `total_cost_usd`, and `modelUsage` (per model, includes subagents). `Query.getContextUsage({detail:'summary'|'full'})` returns `totalTokens`, `maxTokens`, `percentage`, per-category tokens (`'full'` makes token-count API calls that are not billed; `detail` needs SDK 0.3.257+). | Effort | `effort` option at launch (`'low'`/`'medium'`/`'high'`/`'xhigh'`/`'max'`, type `EffortLevel`); `Query.applyFlagSettings({ effortLevel })` mid-session (streaming input only). Sent as `output_config.effort` with beta header `effort-2025-11-24`. Observed on SDK 0.3.319 / Claude Code 2.1.319 (#110): launch `low` reached the API for `claude-sonnet-4-6` and `claude-opus-4-6`; `applyFlagSettings` changed the next request from `low` to `high`. For `claude-sonnet-4-5` the effort was **silently dropped** (no `output_config`; `thinking: {type:'enabled', budget_tokens:31999}` instead). The d.ts says `max` "runs as `'high'` on a model without `'max'` support". `supportedModels()` gives per-model `supportsEffort` and `supportedEffortLevels` offline: `claude-sonnet-4-5` none, `claude-sonnet-4-6` `low`/`medium`/`high`/`max` (no `xhigh`), the 5.x aliases all five. Defaults with no effort set: `claude-sonnet-4-6` sent `high`, the 5.x models `medium`. So the adapter declares `effortSwitch: 'per-turn'` and refuses levels the model does not list; a model id `supportedModels()` does not cover (a dated or custom id) is refused too, since support cannot be confirmed. Residual silent overrides, per the d.ts only: `CLAUDE_CODE_EFFORT_LEVEL` in the environment (the adapter removes it from the Worker's env), and the organization's per-model effort cap and the settings `maxEffortLevel` (not detectable by the adapter; `settingSources: []` avoids the settings files). Like `setModel()`, a change applies from the next model call, so one sent during a turn also reaches that turn's remaining calls. | verified (SDK 0.3.319, by observation against the mock API, #110) | https://code.claude.com/docs/en/agent-sdk/typescript ; `sdk.d.ts` in the pinned package |
| Context window size | `betas: ['context-1m-2025-08-07']` is the only selectable size (`SdkBeta` has no other value); the d.ts says "Sonnet 4/4.5 only". Observed on SDK 0.3.319 / Claude Code 2.1.319 (#110): the binary sends the beta header for every model, it does not filter. So the adapter declares `contextSizes: [1000000]` and refuses it, at launch and on a model switch, for models other than Sonnet 4 and 4.5. | verified (header behaviour, by observation against the mock API, #110); the model restriction is from the d.ts comment only, UNVERIFIED against the platform docs | `sdk.d.ts` in the pinned package |
| Cost reporting | `total_cost_usd` and per-model `costUSD` on `result`; both are client-side estimates from a bundled price table and the docs say not to bill end users from them. Resumed sessions report the whole session total (since v2.1.277), so do not sum across resumes. `maxBudgetUsd` / `--max-budget-usd` cap. | verified | https://code.claude.com/docs/en/agent-sdk/cost-tracking |
| Auth modes | API key (`ANTHROPIC_API_KEY`, Console), Amazon Bedrock, Google Cloud Agent Platform (Vertex), Microsoft Foundry, or the user's own Claude login in the unmodified binary. `--bare` mode never reads OAuth credentials or the keychain and needs an API key / helper / cloud provider creds; `--bare` is recommended for scripted calls and "will become the default for `-p`". | verified | https://code.claude.com/docs/en/headless , https://code.claude.com/docs/en/agent-sdk/overview |
| Per-session MCP config | SDK option `mcpServers` is passed to the binary as JSON in `--mcp-config` on its command line, so headers (the Worker token) are readable in `/proc/<pid>/cmdline` by any local user. `extraArgs: {'mcp-config': <path>}` with a 0600 file keeps the token off the command line; the server still registers (listed in `system/init` `mcp_servers`). The adapter uses the file route and its test scans `/proc` for the token. | verified (SDK 0.3.319, by observation, #11) | `packages/adapters/claude-sdk/src/adapter.conformance.test.ts` |
| MCP tool naming and deferral (#18) | Claude Code 2.1.319 names MCP tools `mcp__<server>__<tool>` and defers them: they are not in the request's `tools` list (only `ToolSearch` and a `DeferredToolPlaceholder` are), yet a direct `tool_use` of `mcp__tacet__escalate` runs it, after a `canUseTool` approval. The HTTP MCP server registered from the `--mcp-config` file (`type: http`, `headers`) receives the call with the configured `Authorization` header. | verified (CLI 2.1.319 via SDK 0.3.319, live with mock, #18) | `packages/mini/src/mcp/claude-worker.test.ts` |
| `result.usage` scope | Covers the turn the `result` ends (all main-loop model calls in it), not the whole session: a turn with one tool call reports two calls' tokens, the next turn starts again. The adapter reports tokens per top-level model call from the stream's `message_start` (prompt tokens incl. cache, served `model`) and `message_delta` (`output_tokens`), with context = prompt + output and the window from `getContextUsage({detail:'summary'})` once per model; subagent calls (`parent_tool_use_id` set) are left out, matching `result.usage`. `total_cost_usd` is cumulative over the session, so the adapter emits its difference in a cost-only event (zero tokens) at each `result`. The adapter remembers each session's last total, so resume and fork also emit differences; if it never saw the total (e.g. after a restart), the first resumed turn reports no cost and only sets the baseline, so that one turn is missing from the ledger. | verified (SDK 0.3.319, by observation, #11) | `packages/adapters/claude-sdk` |
| User message uuid and `sessionId` | `SDKUserMessage.uuid` is optional; `result` declares `user_message_uuid` / `user_message_uuids` and the interrupt receipt lists `still_queued` uuids, which the adapter maps back to input text (non-empty receipts not yet observed). Option `sessionId` (UUID) fixes a new session's id up front; with `resume` + `forkSession` it names the fork. | verified (SDK 0.3.319 type declarations; `sessionId`, resume and fork by conformance run, #11) | https://code.claude.com/docs/en/agent-sdk/typescript |

**Conflict (resolved 2026-11-09):** `docs/RESEARCH.md` section 7 said `claude -p` / Agent SDK usage moved to a separate credit pool from 2026-06-15. The primary help article now says that change is paused and subscription-login usage still draws from plan limits. RESEARCH section 7 was stale on this point and was corrected on 2026-11-09.

**Design rule that follows:** Tacet never touches OAuth tokens. For Claude it launches the user's own `claude` (their login) or passes `ANTHROPIC_API_KEY` from the environment. Whether a Tacet-hosted multi-user service may run subscription logins is out of scope (Tacet is local-first, single user); the owner's setup (own subscription login plus an API key with a $200/month budget) and the default routing are recorded in `docs/RESEARCH.md` section 7. Default: API key for parallel or unattended Workers, subscription login for interactive or single sessions. Whether the "ordinary, individual usage" language covers many parallel Workers on one plan was never ruled on, so the owner decided (#65) that Tacet never does it: `auth.unattended` accepts only `api_key` (see Gaps, item 9).

### CLI vs SDK decision (#64, 2026-11-09)

The Claude adapter uses `@anthropic-ai/claude-agent-sdk`. Raw `claude -p` lacks interrupt (signal only), mid-session model switch and live context usage, and needs an extra MCP process for approvals. The SDK talks to the same binary over an internal control protocol that is only documented as SDK internals. Use `pathToClaudeCodeExecutable` to launch the user's own `claude` where their login should apply. Details, fixtures and the mock harness: [`spikes/64-claude/README.md`](spikes/64-claude/README.md).

## 7. Implications for `AgentAdapter` and `AgentEvent` (from this matrix)

Sketch in `docs/ARCHITECTURE.md` section 3. Not edited here; for the architect/ADR owner.

- `usage` event: `contextMax` is not always known and `costUsd` is usually an estimate or absent. Make `contextUsed`, `contextMax`, `costUsd` optional and add `source: "reported" | "estimated"`. `capabilities()` should say whether live context usage exists (Gemini: no).
- Interrupt is not uniform: Claude returns queued message IDs, others return nothing. `interrupt()` should return `{ stillQueued?: string[] }` or the Mini-conductor must track queued input itself.
- `approval.request` must carry a vendor-neutral option set. Claude gives allow/deny with optional `updatedInput` and permission-rule suggestions; ACP gives allow_once/allow_always/reject_once/reject_always; Codex gives accept/acceptForSession/decline/cancel plus policy amendments, and permission grants scoped to turn or session (#58). `ApprovalDecision` (in `@tacet/core`, #5) has `allow_once | allow_always | reject | cancel` plus an optional input patch, a `persist` flag and an optional grant.
- Fork is a real capability bit; Gemini and ACP v1 lack it. Emulation (start a new session with a HandoffPacket) is already the plan and should be the fallback.
- Model switching differs (per turn, per prompt, mid-session, launch only), so `SessionOptions.model` and `send(..., {model?})` both need to exist, and `capabilities()` must say which are honoured.
- A non-streaming-approval surface (Gemini headless) means approvals have to be pre-decided by `--approval-mode` or the PTY+hooks adapter must be used; capability `approvals: "none"`.
- Effort and context size selection (#110, 2026-11-09). Honest `effortSwitch` per vendor: **Claude `per-turn`** (`applyFlagSettings`; per-model levels from `supportedModels()`, and the SDK drops or lowers unsupported ones silently, so the adapter refuses them) and context sizes **1M only, Sonnet 4/4.5 only** (see section 1). **Codex `per-turn`** (`turn/start.effort`; values come from `model/list.supportedReasoningEfforts`, not a fixed enum) and context sizes **not selectable** (only a clamped `model_context_window` config key, per-thread effect UNVERIFIED, so PARTIAL). **OpenCode `per-turn`** (`variant` string on each prompt, verified in the 1.19.5 spec) and context sizes **not selectable** (pick another model). **Gemini CLI: none for live switching**; thinking budget/level is `settings.json` at launch only, so at most `per-session` by spawning a new process with different settings (PARTIAL, allowed values UNVERIFIED); context sizes **not selectable**. The `capabilities()` effort list must be read from the vendor at runtime (Codex `model/list`), not hard-coded.
- Claude-specific: `result` fires per turn in streaming-input mode and `total_cost_usd` is cumulative for the call; the adapter must take the latest, not sum.
