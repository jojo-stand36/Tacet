## Keeping it fresh

Vendor surfaces under active development change monthly. The `matrix-freshness` CI job (`node scripts/check-matrix-freshness.mjs`, #66) warns a week before an active surface's date is 30 days old and fails after that; it also runs weekly on `main`. A surface's **Checked** date below is the oldest date of its version pin and its rows. To refresh a surface:
1. Re-verify its rows against primary sources (`verify-vendor-facts` skill): at least its version pin in section 0, plus every row a newer version could change.
2. Update the facts and pins that changed, and put the date you checked in each row you re-checked.
3. Set its **Checked** date here.

Do not bump a date without re-checking.

**What `tacet attach` does with this:** these readings differ on malformed input, so attach passes on only well-formed text and sequences (ADR-003, #302 addendum), which most of them read alike. Bytes that are not UTF-8 become U+FFFD and C1 controls are dropped. Within that, attach drops OSC 52 and 5522, OSC 1337 or 50 whose key is `Copy`, `CopyToClipboard` or `EndCopy` (any case), and every DCS but `q`. It also drops ESC sequences that start a string in GNU screen and `ESC %` encoding switches other than `ESC % G`. Known risks: GNU screen was modelled from source, never run, and no terminal here was tested for real, only xterm.js and models of the others. Both are in #311, with restoring non-ASCII titles safely. Other iTerm2 keys, inline images (`File=`) among them, pass.

## 7. Implications for `AgentAdapter` and `AgentEvent` (from this matrix)

Sketch in `docs/ARCHITECTURE.md` section 3. Not edited here; for the architect/ADR owner.

- `usage` event: `contextMax` is not always known and `costUsd` is usually an estimate or absent. Make `contextUsed`, `contextMax`, `costUsd` optional and add `source: "reported" | "estimated"`. `capabilities()` should say whether live context usage exists (Gemini: no).
- Interrupt is not uniform: Claude returns queued message IDs, others return nothing. `interrupt()` should return `{ stillQueued?: string[] }` or the Mini-conductor must track queued input itself.
- `approval.request` must carry a vendor-neutral option set. Claude gives allow/deny with optional `updatedInput` and permission-rule suggestions; ACP gives allow_once/allow_always/reject_once/reject_always; Codex gives accept/acceptForSession/decline/cancel plus policy amendments, and permission grants scoped to turn or session (#58). `ApprovalDecision` (in `@tacet/core`, #5) has `allow_once | allow_always | reject | cancel` plus an optional input patch, a `persist` flag and an optional grant.
- Fork is a real capability bit; Gemini and ACP v1 lack it. Emulation (start a new session with a HandoffPacket) is already the plan and should be the fallback.
- Model switching differs (per turn, per prompt, mid-session, launch only), so `SessionOptions.model` and `send(..., {model?})` both need to exist, and `capabilities()` must say which are honoured.
- A non-streaming-approval surface (Gemini headless) means approvals have to be pre-decided by `--approval-mode` or the PTY+hooks adapter must be used; capability `approvals: "none"`.
- Effort and context size selection (#110, 2026-11-09). Honest `effortSwitch` per vendor: **Claude `per-turn`** (`applyFlagSettings`; per-model levels from `supportedModels()`, and the SDK drops or lowers unsupported ones silently, so the adapter refuses them) and context sizes **1M only, Sonnet 4/4.5 only** (see section 1). **Codex `per-turn`** (`turn/start.effort`; values come from `model/list.supportedReasoningEfforts`, not a fixed enum; Codex lowers unsupported levels and passes unknown names through, so the adapter refuses them) and context sizes **not selectable** (only a clamped `model_context_window` config key, per-thread effect UNVERIFIED, so PARTIAL). **OpenCode `per-turn`** (`variant` string on each prompt, verified in the 1.19.5 spec) and context sizes **not selectable** (pick another model). **Gemini CLI: none for live switching**; thinking budget/level is `settings.json` at launch only, so at most `per-session` by spawning a new process with different settings (PARTIAL, allowed values UNVERIFIED); context sizes **not selectable**. The `capabilities()` effort list must be read from the vendor at runtime (Codex `model/list`), not hard-coded.
- Claude-specific: `result` fires per turn in streaming-input mode and `total_cost_usd` is cumulative for the call; the adapter must take the latest, not sum.
